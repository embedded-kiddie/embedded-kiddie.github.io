UNO R4＋ILI9341（SPI版）タッチとキャリブレーションのアルゴリズムと精度の検証

Nov 12, 2026

はじめに

「XPT2046_Touchscreen ライブラリ で問題ないだろう」と高を括ってましたが、甘かったです。前回 試した以下のパネルのうち、特に 2.4 インチ版で問題が出まくりでした 😩

  • 2.4inch SPI Module ILI9341 SKU:MSP2402 - LCD wiki
  • 2.8inch SPI Module ILI9341 SKU:MSP2807 - LCD wiki

今回はその問題点の分析と対策、およびキャリブレーションアルゴリズムについて報告したいと思います。

使用したソフトウェアは以下の通りです。

  • ArduinoCore-renesas 1.6.0
  • Arduino_GFX 1.6.9 または Adafruit-GFX-Library 1.13.0 + Adafruit_ILI9341 1.7.0
  • XPT2046_Touchscreen 1.4

前回 の続きとしたかったのですが、SPI 版 ST7789 は XPT2046 との両立が確立できず、また 8bit パラレル版 MCUFRIEND タイプのタッチ機能もまだ検証できていません 😓

タッチパネルの向きについて

まず言及すべきは 2.4” 版と 2.8” 版の向きについてです。例えばディスプレイパネルの向きを TFT_ROTATION（0 〜3）とすると、2.4” 版タッチパネルの向き TOUCH_ROTATION は次のようにディスプレイパネルに対して 90° 回転させた

となり、一方 2.8” 版は 180° 回転させた

になります。

「赤い基板」の LCD は類似品が多そうなので、たまたま私が購入したタイプだけなのかも知れません。初めて扱うデバイスの場合、ライブラリの 例題 で動作確認するのが基本です。

動作上の問題点とその対策

試行錯誤しながらの動作テストで判明した問題点を「SPI バスクロックの設定値」と「過渡応答と時定数」とに整理し、その対策として「後処理の実装方針」を検討しました。

SPI バスクロックの設定値

UNO R4 と 2.4” 版 LCD の間にレベル変換モジュールを挟み、それらをデュポンワイヤで接続したところ、画面の至る所で「ノイズ」が検知されるという事象に遭遇しました。

そこでデュポンワイヤをジャンパ線に変え短く繋いだところ、その頻度はかなり減りました。

さらによく調べると、そもそもの原因は「GitHub の issues #60」で指摘された SPI バスクロックの設定にあることが判明しました。XPT2046 のデータシート には３つのノイズ対策が挙げられていて、そのうちの１つが「サンプリング中はクロックを下げる」というものです。

オリジナルのコード では、SPI バスクロックが SPISettings() を介して 2MHz に設定されていますが、これを 1MHz に下げたところ「ノイズ」が出まくる状態は見事に解消されました（ちなみに LovyanGFX の設定 も 1MHz でした）。

XPT2046_Touchscreen は５年も放置されているので、インストール先のソースコードを直接変えちゃって良さそうですネ。

過渡応答と時定数

次に 2.4” 版と 2.8” 版の過渡応答を調べてみました。グラフは画面の左上端をタッチした時のそれぞれの応答です。前者は整定するまで数十ミリ秒かかるのに対し、後者はタッチ直後から比較的安定した値が測定されています。

そこで 2.4” 版についてタッチ時の過渡応答を四隅で測定すると、特にタッチ圧 (z) の整定値が場所ごとに異なりました。

これは、x や y の安定性を z で判定する場合に閾値の調整が必要なこと意味します。実際微妙なチューニングが必要でした。

さらに後述するキャリブレーション後の影響を調べると、一点だけをタッチしたにも関わらず、短時間で広範囲にバラけた点が「外れ値」として測定される結果となりました。

例えば冒頭のリンク先ページに掲載されたデモでは LCDWIKI のライブラリ を使っていて、「５回のサンプリング後、両端を切り捨てた残りで平均値を算出」、即ち「中央値付近を平均化」しています。中央値（メディアン）は「外れ値」を除外する妥当な手法です。

一方 XPT2046_Touchscreen では、２回のサンプリング値を単純平均 しているだけなので、こういったハードウェア側の特性違いによる「外れ値」的なノイズを弾くことが出来ません。それはアプリ側の「後処理」の役割と割り切っているのだと思います。

後処理の実装方針

前章での分析を踏まえれば、「後処理」としては次の要件を満たすことが理想的です。

  • ハードウェアの特性の違いに左右されないこと
  • 微妙な閾値の調整に頼ることなく、ロジックで対処すること

これらを満たすには、「少なくとも x と y が整定したことを判定する」のが妥当でしょう。例えば、一定の窓枠を時系列方向にスライドさせ、移動平均と出力値との差や、分散や標準偏差を判定の基準とする方法に落とし込むことが考えられます。

今回は計算を軽くするため、移動平均の代替として一次ローパルフィルタを使ってみました。サンプリング周期を 1msec、時定数 を 10msec とすることで、タッチ開始から座標の確定まで 20msec 程度という、ソコソコの結果が得られました。ゲームなどリアルタイム性を重視するアプリへの適用は苦しいですが、UNO R4 の GUI なら実用上は問題ないレベルだと思います。

キャリブレーションのアルゴリズムと実装

幾何学的補正モデルとアルゴリズムの概要

Arduino 用の小型 LCD のキャリブレーションには、ディスプレイパネルとタッチパネルの物理的ズレや歪みを補正する幾何学的モデルにアフィン変換を使うのが一般的です。そのモデルと解法を組み合わせた代表的な実例を以下に示します。

最大範囲／最小範囲に基づく単純な線形変換によるキャリブレーション

タッチパネル座標系の最大範囲と最小範囲をディスプレイパネルの座標系にマッピングすることで「平行移動」と「拡大縮小」の物理的なズレを補正します。

具体的には、ディスプレイパネルの四隅でタッチパネルの出力値を拾い、x、y それぞれ独立に平均化した最大値と最小値を map 関数 などでディスプレイパネルの範囲内に変換します。

このアルゴリズムは、TFT_eSPI のキャリブレーション で採用されています。

２点、または３点キャリブレーション

それぞれのキャリブレーションの原理と解法の概要は、以下の Google 検索で確認してください（Google って便利 😁）。

  • LCD ディスプレイパネルとタッチパネル ２点キャリブレーションの原理と解法
  • LCD ディスプレイパネルとタッチパネル ３点キャリブレーションの原理と解法

２点キャリブレーションのプログラムが「Calibrating and Coding Your Arduino Touchscreen – Bytes N Bits」に公開されています。

４点（またはそれ以上）キャリブレーション

「平行移動／拡大縮小」に「回転」と「剪断（四角形を平行四辺形にする変形）」を加えたモデルで、４点以上のサンプル点から６個のアフィン変換係数を求めます。

LovyanGFX のキャリブレーション では、最小二乗法から導き出される正規方程式 の解をガウスの消去法で求めるアルゴリズムを実装しています。

ChatGPT に投げたプロンプト

抵抗膜式タッチパネルをキャリブレーションする数式を導出し、プログラムを作成してください。問題を解くためのプロセスの概要をプロンプトとしてテキストファイルに記述したので、アップロードします。 同プロンプトを解読し、誤りがあれば指摘し、また可能か否かを回答してください。 ただし、プロンプトに含まれる数学記号「Σ」には、それに付随する「i = 0」や「n」などの記号を省略しているので注意してください。

  1. 想定する座標 (X, Y) に対し、実際に観測された値が (x, y) であったとします。
  2. キャリブレーションは X = ax + by + c、Y = dx + ey + f で表されるアフィン変換で行うとします。
  3. タッチパネルの4隅の座標を複数回観測し、それらの観測値から最小二乗法で a, b, c, d, e, f を算出するものとします。
  4. X, Yに関する残差平方和 E はそれぞれ次になります。 Ex = Σ(Xi - (axi + byi + c))^2、Ey = Σ(Yi - (dxi + eyi + f))^2
  5. これら残差平方和が最小になるための条件を ∂Ex/∂a = 0、∂Ex/∂b = 0、∂Ex/∂c = 0、∂Ey/∂d = 0、∂Ey/∂e = 0、∂Ey/∂f = 0 とします。
  6. これら6本の連立方程式をC言語で算出するためのプログラムを記述してください。
  7. ただし連立方程式の解は、ガウスの消去法以外の方法で算出することとします。
  8. また以上の各段階で検証可能な式を導出し、最終的に a ~ f を算出するアルゴリズムをまとめて下さい。

キャリブレーション精度の検証

精度の検証は、定量的に検証する方法が思いつけなかったので、キャリブレーション後に表示される四角形をペンでなぞり、目視で行いました。また比較対象として LovyanGFX の例題 を実行したところ、若干劣るものの（手持ちの 2.4” LCD で、特定の１辺の合いが悪い）、まぁまぁの出来 🙄 かと思います。

まとめ

UNO R4 で動作する LCD と定番の XPT2046_Touchscreen ライブラリ 組み合わせたところ、特に 2.4” 版 LCD で酷いノイズとタッチ後の立ち上がりの遅さに悩まされました。

これに対処するため、同ライブラリを継承したクラスを作成し、ノイズを除去するローパスフィルタと４点キャリブレーションを組み込んだところ、何とか実用に耐えられそうな（？）ところまで漕ぎ着くことが出来ました。

しかしより根本的には、XPT2046 のデータシート に記載されたノイズ対策を試すべきだと思います。いや、いっその事、Lovyan03 さんのタッチ関連コードを丸ごと移植した方が良いかも知れません。本編では述べませんでしたが、今回作成したキャリブレーションはパネルの向き（ローテーション）を変える毎に再実行が必要ですが、LovyanGFX ではパネルの向きに依存しない工夫をしています。さらに ビットバン方式もサポート している優れものです。

誰かが移植してくれることを願いつつ（他力本願 😮‍💨）、本記事を〆たいと思います。
